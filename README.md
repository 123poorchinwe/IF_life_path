# IF人生线：未开放区域

《IF人生线：未开放区域》是一款面向毕业生与职业转型者的AI职业决策模拟器。它不会通过性格测试替用户选择“最适合的职业”，而是把用户的真实经历拆解成能力、资格、证据与限制，再通过职业地图和情景互动帮助用户看清不同选择的进入条件、机会成本与风险。

> 你看见的职业，只是当前能够识别的部分。

## 产品目标

用户完成一次体验后，应能够回答：

- 我当前有哪些真实可进入的职业路径？
- 哪些路径只缺少一两项可以补足的条件？
- 哪些岗位存在专业、学历、身份或时间窗口等硬门槛？
- 我的项目经历可以迁移到哪些相邻行业？
- 我对稳定、收入、自主、成长与风险的取舍是什么？
- 下一步可以进行哪些低成本、可验证的现实实验？

产品不承诺录取、Offer或考试结果，不提供虚假的职业匹配百分比，也不会把模糊的“相关专业”自动解释为符合资格。

## 当前MVP

项目已经实现一条可本地运行的体验闭环：

```text
建立档案 → AI卡牌确认 → 职业地图 → 情景模拟
        → 能力重组 → 职业结论
```

目前包含：

- 事实、推断、能力、资格、限制和偏好卡片；
- 30个职业节点及不同职业门状态；
- 职业关系网络与像素区域地图；
- Phaser实时2D地图底座；
- 玩家移动、镜头跟随、碰撞和NPC巡逻；
- 建筑入口、室内场景与NPC自由输入对话；
- 8类核心NPC人物设定；
- 40个结构化事件骨架；
- 六阶段时间与资源状态；
- 能力迁移和职业结论页面；
- 硅基流动/ModelScope兼容对话接口与本地回退；
- 桌面端和移动端响应式布局。

## 职业门状态

系统不用单一匹配分数，而是显示可解释状态：

| 状态 | 含义 |
| --- | --- |
| 已开放 | 当前具备主要进入条件，可以开始投递或进一步核验 |
| 接近开放 | 缺少一至两项可补条件，例如SQL、作品或行业案例 |
| 需要调查 | 招聘表述或专业要求存在歧义，不能由AI直接下结论 |
| 硬性受限 | 存在明确的专业、学历、身份、年限或资格门槛 |
| 时间敏感 | 受到秋招、考试、申请或应届身份窗口影响 |
| 新发现 | 能力迁移关系成立，但仍需要现实岗位证据支持 |

## AI与规则的边界

项目严格区分三层：

1. **规则层**：计算职业硬门槛、时间、精力、资金、信息质量和关系变化。
2. **AI层**：负责档案解析、能力迁移解释、NPC自然对话和情景表达。
3. **表现层**：负责职业网络、像素地图、室内场景、证据标签和结果报告。

AI不能直接修改游戏数值、资格条件或职业门状态。模型输出需要经过Zod校验，后果只能以语义标签进入确定性规则引擎。

## NPC设计

NPC不是简单的好人或坏人。每个人具有稳定的：

- 身份与经历；
- 职责与可用资源；
- 当前目标和组织压力；
- 知识范围与信息盲区；
- 说话方式和压力反应；
- 利益一致程度和权力差；
- 对玩家互动的连续记忆。

AI负责实时生成自然语言，但必须遵守人物设定。NPC可以犹豫、误解、反问、改口或拒绝回答，却不能突然改变核心经历、价值倾向或凭空知道职责之外的信息。

## 配置AI对话

复制环境变量模板：

```powershell
Copy-Item .env.example .env.local
```

在`.env.local`中配置：

```env
AI_PROVIDER=siliconflow
AI_BASE_URL=https://api.siliconflow.cn/v1
AI_MODEL=Qwen/Qwen2.5-7B-Instruct
SILICONFLOW_API_KEY=你的服务端API密钥
```

如果Vercel中已有同名旧变量无法覆盖，可以改用带`1`的迁移变量：`AI_PROVIDER1`、`AI_BASE_URL1`、`AI_MODEL1`、`SILICONFLOW_API_KEY1`和`AI_MOCK_MODE1`。程序会优先读取它们。

重新运行`npm run dev`。接口成功时，NPC对话会显示AI在线；密钥缺失、网络异常或模型输出校验失败时，系统会切换到本地回退，不阻断主要流程。

### 安全说明

- `.env.local`不会提交到Git；
- Token只在服务端API路由中读取；
- 浏览器端不会获得服务端Token；
- 不要把真实密钥写入README、源码或`.env.example`；
- 如果密钥曾经出现在聊天、截图或公开提交中，请立即轮换。

## 数据与内容说明

当前职业和岗位内容主要用于MVP交互验证，不构成现实招聘建议。正式使用前需要：

- 接入可追溯的官方招聘公告与授权数据来源；
- 保存原始岗位文本、来源链接、发布日期和截止日期；
- 对专业目录、应届身份、证书和工作年限进行逐岗核验；
- 区分官方证据、多个来源、单一经验和AI推断；
- 对已过期岗位进行自动标记和复核。

## 当前限制

- 免费模型存在固定速率限制；达到上限或请求异常时会自动使用本地回退；
- 像素人物仍使用程序生成的临时精灵，尚未接入正式四方向Sprite Sheet；
- 地图碰撞区域目前为手工配置，尚未使用Tiled瓦片碰撞层；
- NPC巡逻已接入Phaser，但完整日程和长期记忆仍在开发；
- 岗位数据尚未接入正式抓取或授权数据源；
- Supabase持久化与账号系统暂未接入。

## 2026-08 可玩版本更新

当前版本已经完成一条“地图调查—证据归档—AI交涉—规则裁决—职业门变化”的纵向切片：

- Phaser 像素小镇支持角色移动、碰撞、镜头跟随和地点进入；
- 地图内可以调查原始任务消息、合同样本和岗位任务样本；
- 地图取得的证据会自动带入对应任务，而不是仅作为装饰收藏；
- 3 个作者设定任务支持自由文字输入、意图解析、NPC决策、AI台词和确定性结局；
- NPC具有固定人物底色、长期记忆、地点到访记录和分时段日程；
- 任务结局会回写地点等级、职业证据和职业门状态；
- AI服务不可用时启用本地回退，规则层与主要流程仍可运行。

部署到托管平台时，需要在服务端设置`.env.example`中列出的环境变量。真实Token只能保存在托管平台的加密环境变量中，不能提交到GitHub。

## CloudBase存档（准备中）

国内版使用上海地域CloudBase环境保存账号与游戏进度。浏览器端只允许配置`NEXT_PUBLIC_CLOUDBASE_PUBLISHABLE_KEY`，禁止把service role或管理员API Key写入仓库。接入云同步前，需要在CloudBase控制台添加站点安全来源域名，并为存档集合配置按用户隔离的安全规则。未完成云端配置时，当前页面、规则状态和任务对话仍会自动保存在浏览器本地。
